# 2026-11-28 系统审核与治理

基线为 `11d9d98`。审核范围覆盖应用组合、12 个内部包、语言与菜单入口、设置、Windows 适配、构建、仓库检查和 CI。最近提交重点检查 `b83c552` 的增强功能、`9da012f` 的设置行为、`a6127d6` 的菜单与设置分类，以及 `80f335d` 的原生安装器适配。

本轮以有证据的问题为边界进行治理，保留 Go/nsgo、已有功能与配置格式。没有新增外部依赖，也没有修改产品版本或创建正式发布。

## 修复与依据

| 压缩包中大小写不同的路径被合并 | 压缩包使用精确路径，Windows 文件夹保留大小写不敏感规则 | `TestArchivePathsKeepTheirCase` |
| 更新协议校验不完整，失败下载可覆盖已验证安装器；定时清理可能干扰另一窗口 | 校验标签前缀、摘要字符和大小；临时下载校验后替换；取消定时删除共享目录 | `internal/update` 测试；核对 nsgo 原生安装器仍支持 `/S /RELAUNCH` |

## 测量

Windows 11、i7-12700K，Go 1.27.4、nsgo v0.3.4。新旧应用与 deskrun 均先编译，再在私有桌面交替运行各 5 次。样本为固定随机种子生成的 10 张 6000×4000 JPEG，默认画质设置，独立配置目录，连续翻图间隔 180 ms。数据用于本机回归比较，不代表冷启动分位数或全格式性能。

| 指标 | 基线 | 本轮加载与调度改动 |
| --- | --- | --- |
| 窗口可见时间，5 次，ms | 900、690、662、651、650 | 647、660、664、661、661 |
| 中位数，ms | 662 | 661 |
| 翻图后私有内存中位数，MiB | 646.8 | 651.6 |
| 翻图后工作集中位数，MiB | 417.5 | 422.1 |
| 累计 CPU 时间中位数，s | 5.8125 | 5.625 |

首图、内存和 CPU 差异不足以宣称整体提速或减内存。所有运行的主窗口响应检查和退出检查均通过。可见时间由既有 deskrun 记录；应用仍有一秒超时显示兜底，因此它不是任意格式下精确的首图时间。

资源限制有实际代价：`BenchmarkRegion6000x4000` 将已解码图缩至 1500×1000，原来按 20 个逻辑处理器分派工作，3 组每组 3 次约为 22.1–23.3 ms；限制在调用线程后为 170.0–180.6 ms。它使 BMP/TIFF 等大像素图的平滑覆盖层较晚出现，但不会在后台占用全部线程。JPEG/PNG/WebP 常用路径仍使用 WIC 缩小解码。未来如需进一步提速，应在保持并发上限和像素等价的前提下优化算法。

## 验证范围与限制

- 收尾结果：`python tools/check.py` 检查 138 个暂存文件、25 项仓库测试通过；`go test -tags nodynamic ./internal/...` 的 12 个包通过；在 `cmd/freeview` 中执行的 `go tool nsgo check` 通过，`go tool nsgo test` 的 35 项应用测试通过
- 保留原有应用行为测试；新增测试覆盖文件操作、重复读取、任务取消、配置并发、格式边界和下载协议
- 私有桌面实测滚轮、侧键、中键、右键菜单勾选、重命名与取消、七页设置、设置关闭与重开，并检查响应和退出；截图确认显示内容与当前路径一致
- 稳定版于本次任务核对：[Go 官方下载列表](https://go.dev/dl/)、[nsgo v0.3.4](https://github.com/nsgo-dev/nsgo/releases/tag/v0.3.4)
- 原生安装器继续验证应用、卸载器、GPL、模块许可和内嵌组件许可；没有运行真实自动更新替换已安装程序
- 未覆盖新的显示器 ICC 切换矩阵、真实 RAR/TAR 样本以及所有 RAW 编码器；既有[已知限制](roadmap.md)继续保留
- 正在执行的系统解码不能强制中断；当前实现取消未开始的工作并拒绝过期结果
- 多进程同时修改配置仍是最后一次成功写入生效，不提供跨进程字段合并

这次审核建立了更清晰的改动边界并修复已复现的问题，不代表所有模块已经不存在缺陷，也不以文件拆分代替行为和性能验证。
